# 内部阶段：主题整理

目标：把 Families 组织成少量、可理解、以问题为中心的 Theme，用于导航和后续蒸馏。

## Theme 规则

- 每个 Theme 必须有自然中文名称、中心问题、纳入条件和排除条件。
- Theme 回答“这些知识共同解决什么问题”，不是简单复刻标签或文件夹。
- 允许跨原始标签聚合，但不能因为都属于一个宽泛领域就硬合并。
- 所有 Family 必须被 Theme 覆盖；不得孤立。
- `major_change` 只有在真正出现新核心主题、核心主题合并或拆分时才标记；不要为了触发 Gate 而夸大变化。
- 必须对照 `user_brief`：当前高层结构是否覆盖本轮用户真正想整理出的成果。

## 用户审核原则

这是默认第一个高价值软检查点。用户只需要判断主题结构是否跑偏、遗漏、误合并、误拆分或命名不清；不要重新展示全部 Claim/Families 让用户从头审核。
