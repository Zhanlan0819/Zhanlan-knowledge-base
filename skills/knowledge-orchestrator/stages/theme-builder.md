# 内部阶段：主题整理｜v0.7 知识图谱归属

目标：把 Families 组织成以真实问题为中心、粒度清晰的 Theme。Theme 是知识导航视图，不是唯一归属的文件夹。

## Theme 规则

- 每个 Theme 必须有自然中文名称、中心问题、纳入条件和排除条件。
- Theme 回答“这些知识共同解决什么具体问题”，不是简单复刻标签或文件夹。
- **Theme 数量不是优化目标。** 不得为了降低审核数量，把多个独立问题压成一个超级主题。
- 如果一个 Theme 的中心问题必须用“以及 / 同时 / 与 / 和……”连接两个可以独立回答的问题，优先拆分。
- 如果两组 Family 会分别形成独立文章、清单、决策标准、工作流或产品模块，默认视为两个 Theme，除非存在明确的共同核心问题。
- 同属“个人 IP / 商业 / AI / 家庭教育”等大领域，只能说明它们可能相关，不能作为合并理由。
- 所有 Family 至少进入一个 Theme，不得孤立。

## 主归属 + 跨主题引用

知识是网络，不是单一路径目录：

- 每个 Family 必须恰好有一个主 Theme，写入该 Theme 的 `primary_family_ids`。
- 同一个 Family 可以同时出现在其它 Theme 的 `family_ids` 中，作为次级引用。
- 次级引用不复制 Claim、不复制 Family，只建立导航关系。
- `primary_family_ids` 必须是当前 Theme 的 `family_ids` 子集。
- 选择主 Theme 的标准：哪个问题域最直接解释这条 Family 的核心用途，而不是哪个 Theme 名字更大。
- 跨主题引用的目的，是保留真实复用关系，不是把所有相关内容互相挂满。

## 质量检查

提交前逐个 Theme 问：

1. 能否用一个具体问题概括？
2. 删除其中任一大块内容后，中心问题是否仍然不变？如果会变，可能需要拆分。
3. 是否只是因为“都属于同一大类”才被放在一起？如果是，必须重做。
4. 是否有 Family 为了二选一而被迫放弃另一个真实用途？如果有，使用次级引用，而不是强制单归属。
5. 用户连续看到这些 Theme 时，能否清楚区分各自解决的问题？

`major_change` 只有在真正出现新核心主题、核心主题合并或拆分时才标记；不要为了触发 Gate 而夸大变化。必须对照 user_brief 检查高层结构是否覆盖本轮成果。

## 用户审核原则

这是默认第一个高价值软检查点。用户只需要判断主题结构是否跑偏、遗漏、误合并、误拆分、跨主题引用不合理或命名不清；不要重新展示全部 Claim/Families 让用户从头审核。
